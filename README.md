# Roll20-лист «Благословенного прилива»

Прототип листа персонажа-коммерсанта и кооператива. Он содержит карточные подсказки для выбора персонажа и команды, блок судна с расчётом характеристик по классу и составу экипажа, проверку Collision Engine и безопасное пополнение пенсионного счёта. Путевые показатели рассчитываются для одного сектора; кнопка «Пройти сектор» списывает запасы, добавляет смуту и время пути. «Откатить сектор» однократно отменяет последний переход, сохраняя последующие изменения ресурсов и не отменяя бросков. «Психотерапия» снижает смуту по результатам проверки без ограничения по вахтам (половина d6 округляется вниз), а «Нарастить смуту» добавляет выбранное количество или результат броска.

## Коммерсант

Метки удачи можно свободно менять счётчиком и кнопками «−»/«+», без покупки и автоматического списания денег. Раны отмечаются так же, как поломы судна: обычная отметка сменяется черепом на смертельном пороге. Порог зависит от прошлого; для малохольного Обделённого предусмотрен отдельный флажок. Пенсия показывает расстояние до следующего порога и поздравляет с пересечением каждого из восьми порогов, включая несколько за одно пополнение. Отпуск и приобретение черт остаются решениями игроков.

На лист вынесены спецходы специальностей, памятки прошлого, контекстные проверки и таблицы, а также броски для отдельных историй найма. Результаты сохраняются на листе и выводятся в чат; сами по себе они не меняют деньги, запасы, раны или кооператив. Встреча Игрока с результатом 6 предлагает два дополнительных броска кнопкой по той же таблице. Дополнительные достоинства и недостатки добавляются повторяемыми строками; прежние основные поля сохранены, чтобы не потерять данные существующих героев.

Небольшие кнопки с костью заменяют только соседнее поле случайным вариантом. Прошлое и черты выбираются по 3d6. Для имён, фамилий и мечт используется равновероятный выбор из опубликованных вариантов: в локальном тексте таблица имён обозначена как 4d6, но содержит только строки 4–18, а таблица мечт обозначена как 2d6, но содержит десять вариантов. Специальность и история найма также выбираются равновероятно. Это не мастер создания персонажа: сочетаемость вариантов и использование ограниченных по времени способностей проверяет группа.

## Разработка

Требуется Node.js 18+; зависимости npm не используются.

```sh
npm test
npm run test:ui
```

`npm test` собирает пакет и запускает unit-тесты на встроенном `node:test`. `test:ui` дополнительно открывает собранную разметку в Chromium через установленный Python Playwright; для этой команды нужен установленный Playwright и браузер Chromium.

Исходники находятся в `src/`. `npm run build` встраивает `src/worker.js` и проверенные правила из `src/rules.js` в единый блок Sheet Worker и создаёт `dist/ouw25.html` и `dist/ouw25.css`. Каталог `dist/` можно загрузить в Custom Sheet Sandbox или использовать при ручном тестировании в Roll20.

## Макрос типовой проверки

Создайте в Roll20 макрос, например `Проверка удачи/неудачи`, и вставьте:

```text
&{template:default} {{name=Проверка удачи/неудачи}} {{Шестёрки минус осложнения=[[ [[ [[4+?{Дополнительные d6|0}]]d6>6 ]] - ?{Осложнения|0} ]]}}
```

Макрос спрашивает, сколько d6 добавить к базовым четырём, и сколько осложнений вычесть. Бросок выполняется один раз: `>6` в Roll20 считает успехом только максимальное значение d6, шестёрки отмечаются в броске, а осложнения вычитаются из их количества. При осложнениях больше числа шестёрок итог будет отрицательным. Подсказка Roll20 показывает сами выпавшие кости.

## Ограничения прототипа

- Sheet Worker, roll query и элементы `progress` необходимо окончательно проверить в живой игре через интерфейс Roll20; локальные тесты моделируют API, но не заменяют такую проверку.
- Описания выбора сокращены для удобства бланка; полный текст правил остаётся в книге.
- Пенсионный баланс защищён от случайного редактирования в интерфейсе листа, но не является серверной защитой от владельца персонажа или API.
- Форсаж и иллюминация реализованы как взаимоисключающие режимы согласно таблице расходов.
- В проект пока не включены сторонние фрагменты кода, изображения, шрифты или готовый пакет для публикации в Community Sheets.
